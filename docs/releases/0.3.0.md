## What's new

- **A settings file for the project.** List the stand-ins your tests may reach in `testing/airgap.yaml`, each with
  the reason it's allowed, and set the mode there too
  ([schema](https://github.com/fiftiesHousewife/under-test-airgap/blob/main/schema/airgap-settings.schema.json)). The
  Gradle plugin hands it to the agent, and the agent finds it on its own in the folder a JVM starts in. A mistake in
  the file stops the run at start, saying what's wrong and on which line. The build's `airgap { mode }` now overrides
  the file's mode only when the build sets it.

## Fixed

- **Mockito's inline mock maker works under the agent.** On JDK 9 and later, Mockito 5 starts a second `java`
  program to attach itself to the test JVM, and the agent refused it, so tests that use mocks failed. The plugin and
  the try-it script now let test JVMs attach agents to themselves (`-Djdk.attach.allowAttachSelf=true`), so no
  program starts. If you name the agent by hand, add that setting to your test JVMs too.
- **Mockito works on JDK 8 too.** The JDK's own `attach` library, loaded from `tools.jar`, is now recognised as the
  JDK's own: a library whose file is in the JDK's own library folder is the JDK's, whoever asks for it.

- **The summary lists an unpacked native library once.** sqlite-jdbc and Netty unpack their native code to a new,
  randomly named file each run; `calls-summary.json` now shows each such library once, as the `native:` entry that
  would allow it (`sqlite-3.36.0.3-*-libsqlitejdbc.jnilib`). The report keeps every file's path.

## Proved

- Calls through Apache HttpClient 4 and 5, OkHttp, Netty, and the PostgreSQL and MySQL JDBC drivers are refused and
  reported, on JDK 8, 11, 17, 21 and 25.
- The agent works alongside JaCoCo, Mockito's inline mock maker and PIT, on every JDK each supports.
- Real projects' tests pass under the agent: Spring PetClinic, and the RealWorld example app with SQLite allowed in
  its settings file.
